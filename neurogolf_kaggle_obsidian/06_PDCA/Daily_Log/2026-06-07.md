## Decision

task071は直接ONNX loweringしない。高gainではあるが、単純eraseでも小feature ruleでもないため、次はzero mask/source-color copy direction分離のcompiler診断へ進む。

task366は最大gain級のCROP_SHAPE候補だが、naive cropではなくobject-marker copy ruleとして解く。次のscore-producing作業はexp080 ruleのcost-aware ONNX lowering。

task366 loweringはstatic template enumerationではなく、small object/marker countを使う構造compilerにする。

task366 loweringでは30x30 full-grid primitiveを積まない。small patch / sparse coordinate routeへ寄せる。

small sparse coordinate routeも標準ONNXでは重い。task366はrule hitとして保持し、次のscore-producing探索は低cost artifactに近いlaneへ戻す。

task365はtask366より600級loweringに近い。次はrectangle-window selector ONNX cost proxyを作る。

task365 full single-modelを `cost<=600` にするのは、6x6 crop memory floorのため厳しい。HTMLのFREE-op小領域化は有効だが、task365は大幅削減候補として扱い、250〜600級の主候補は最大output areaが小さいcrop taskへ広げる。

task185は新しいrule hitとして保持する。ただしConv型homogeneous block判定は600級に届かないため、次は非Conv equality encodingか既存artifact surgeryを試す。

task185の非Conv equality routeも下げる。新規ONNX loweringは中間tensor costが支配的なので、次は既存artifact surgeryまたはよりfusedな表現を探す。

task048は新しい1x1 rule hitとして保持する。ただしnaive connectivity unrollは8x8でも高costなので、次は既存artifact surgeryまたはclosed-form path特徴へ寄せる。

ユーザー提供zipはdrop-inでは使わない。公式one-hotへ直接1ノードで書けるテンプレートだけをtaxonomyとして活用する。30x30中間tensorを作る複合テンプレートは事前にcost gateで弾く。

Python grid上の単純幾何hitは公式one-hotで必ず再検証する。可変サイズgridではpaddingを動かさないshape-aware transformが必要で、full-grid 1ノードflip/rotは基本的に不適。

full-grid 1ノードtemplate routeは主戦力ではない。全例30x30 taskが少なく、hitも0だったため、次はshape-aware低cost compilerかartifact surgeryへ戻す。

shape-aware flip/rot template routeも現時点ではscore-producingではない。固定3x3ならpadding mismatchは解けるが既存artifactにcostで負け、可変shapeでは静的branchが必要になる。zip由来templateはtaxonomyとして残し、主戦力は小出力closed-form rule、artifact surgery、既存低cost artifact miningへ戻す。
